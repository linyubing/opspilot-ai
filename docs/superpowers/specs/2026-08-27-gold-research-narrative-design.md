# 黄金研究大模型解读设计

## 1. 目标

在现有黄金确定性研究快照之上增加可追溯的大模型解读能力。解读只解释数据库中已经正式留痕的真实快照，不修改指标、不补充未经验证的新闻，不输出价格预测、涨跌概率或交易建议。

首个版本使用 GLM-4.7，将结构化快照转换为结构化中文研究报告，并保存快照、模型、提示词版本和生成结果之间的对应关系。

## 2. 范围

本阶段包含：

- 按正式快照 ID 生成黄金研究解读；
- 分别解释实际利率和广义美元指数两个因子；
- 校验大模型结构化返回和金融安全边界；
- 幂等保存解读结果；
- 查询同一快照在不同模型或提示词版本下的历史解读；
- 记录模型名称、提示词版本、提示词摘要和原始响应。

本阶段不包含：

- 新闻、研报或社交媒体检索；
- RAG 证据增强；
- 黄金目标价、涨跌概率、仓位、止损或买卖建议；
- 自动交易或模拟开仓；
- 对模型输出进行多轮自动修复。

## 3. 核心原则

1. **真实输入**：模型输入只能来自已保存的 `gold_research_snapshot`。
2. **确定性优先**：指标和因子状态由 Java 规则计算，大模型无权重新计算或覆盖。
3. **结构化输出**：模型必须返回固定 JSON 合同，不接受自由格式散文。
4. **先校验后保存**：格式、长度或安全校验失败时，不写入正式解读表。
5. **可追溯**：每条解读关联快照 ID、模型、提示词版本和提示词摘要。
6. **版本隔离**：同一快照可保留不同模型或提示词版本的解读，用于后续质量比较。

## 4. 方案选择

采用独立的研究解读网关，不复用通用 `ChatGateway`，也不接入当前 RAG 流程。

原因：

- 通用聊天接口只有字符串输入和输出，无法稳定表达金融研究结构和模型元数据；
- 研究解读需要独立的提示词、安全校验和异常语义；
- 当前没有带来源、发布时间和引用验证的可信新闻链路，提前接入 RAG 会增加假新闻风险；
- 独立网关便于未来替换模型或增加可信证据上下文，不影响普通聊天。

## 5. 领域模型

### 5.1 模型生成结果

`ResearchNarrativeContent` 保存模型经过解析后的内容：

- `summary`：一句话概括两个因子的当前含义；
- `realRateAnalysis`：实际利率因子解读；
- `dollarIndexAnalysis`：广义美元指数因子解读；
- `risks`：风险和局限列表；
- `watchList`：下一次需要观察的指标变化列表；
- `disclaimer`：不构成预测、交易或投资建议的声明。

### 5.2 正式解读记录

`StoredResearchNarrative` 在生成内容之外保存：

- 解读 ID；
- 正式快照 ID；
- 模型名称；
- 提示词版本；
- 提示词 SHA-256 摘要；
- 模型原始响应；
- 生成时间。

## 6. 组件职责

### `GoldResearchNarrativeService`

按快照 ID 编排查询、幂等检查、提示词构建、模型调用、结果校验和正式保存。它不拼装提示词，不解析模型厂商响应，也不直接执行 SQL。

### `ResearchNarrativePromptBuilder`

把正式快照转换为稳定的中文提示词。提示词必须包含数据日期、黄金收益、实际利率变化、广义美元指数变化、两个确定性因子状态和解释，并明确列出禁止生成的内容。首个版本为 `gold-narrative-prompt-v1`。

### `ResearchNarrativeGateway`

金融研究专用模型端口，接收已经构造好的提示词，返回模型名称、原始响应和解析后的结构化内容。

### `SpringAiResearchNarrativeGateway`

使用 Spring AI 和 GLM-4.7 调用模型，并将 JSON 响应解析为 `ResearchNarrativeContent`。模型请求失败统一转换为研究解读上游异常。

### `ResearchNarrativeValidator`

验证必填字段、集合数量、文本长度和金融安全边界。它拒绝包含明确行动指令或预测内容的报告，例如“建议买入”“建议卖出”“目标价”“止损位”和明确涨跌概率。

### `ResearchNarrativeRepository`

负责按幂等键查询、保存和按快照 ID 查询历史解读。

### `GoldResearchNarrativeController`

只负责 HTTP 参数和响应映射，不承担提示词构建、模型调用或校验。

## 7. 数据流

```text
客户端提交正式快照 ID
  -> 查询 gold_research_snapshot
  -> 按 snapshot_id + model_name + prompt_version 查询已有解读
  -> 已存在时直接返回已有记录
  -> 构建只包含真实快照数据的提示词
  -> 调用 GLM-4.7 生成结构化 JSON
  -> 解析并执行格式与安全校验
  -> 幂等写入 gold_research_narrative
  -> 返回正式中文研究解读
```

服务在模型调用前执行幂等查询，减少重复费用；数据库唯一约束负责处理并发请求的最终幂等。

## 8. 数据库设计

使用 Flyway `V6` 新增 `gold_research_narrative`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | `uuid` | 主键 |
| `snapshot_id` | `uuid` | 外键，关联正式黄金研究快照 |
| `summary` | `varchar(500)` | 一句话摘要 |
| `real_rate_analysis` | `text` | 实际利率解读 |
| `dollar_index_analysis` | `text` | 广义美元指数解读 |
| `risks` | `jsonb` | 风险和局限列表 |
| `watch_list` | `jsonb` | 后续观察项列表 |
| `disclaimer` | `varchar(500)` | 免责声明 |
| `model_name` | `varchar(100)` | 实际调用模型 |
| `prompt_version` | `varchar(64)` | 提示词版本 |
| `prompt_hash` | `char(64)` | 提示词 SHA-256 摘要 |
| `raw_response` | `text` | 模型原始响应 |
| `created_at` | `timestamptz` | 生成时间 |

唯一约束为：

```text
snapshot_id + model_name + prompt_version
```

所有 SQL 关键字、表名和字段名统一小写。

## 9. HTTP 合同

### 生成或读取已有解读

```http
post /api/research/gold/snapshots/{snapshotId}/narratives
```

- 首次成功生成：`201`，`created=true`；
- 相同幂等键已存在：`200`，`created=false`；
- 响应包含正式解读记录，不暴露完整提示词。

### 查询快照的历史解读

```http
get /api/research/gold/snapshots/{snapshotId}/narratives
```

按生成时间倒序返回该快照所有模型和提示词版本的正式解读。

不提供自由输入行情或自由输入提示词的研究接口。

## 10. 失败处理

| 场景 | HTTP | 错误码 | 是否保存 |
|---|---:|---|---|
| 正式快照不存在 | 404 | `GOLD_RESEARCH_SNAPSHOT_NOT_FOUND` | 否 |
| 大模型不可用 | 503 | `RESEARCH_AI_UNAVAILABLE` | 否 |
| 模型返回无法解析或字段缺失 | 502 | `INVALID_RESEARCH_AI_RESPONSE` | 否 |
| 解读违反金融安全边界 | 422 | `UNSAFE_RESEARCH_NARRATIVE` | 否 |
| 并发重复生成 | 200 | 无 | 返回数据库中最终保留的记录 |

第一阶段不自动调用模型修复格式错误。失败必须可见，以便定位模型、提示词或解析器问题，并避免隐藏额外费用。

## 11. 校验规则

- 所有文本字段去除首尾空白后必须非空；
- `summary` 和 `disclaimer` 不超过 500 个字符；
- 两个因子分析分别不超过 2000 个字符；
- `risks` 和 `watchList` 各包含 1 到 5 条，每条不超过 300 个字符；
- 禁止出现明确交易指令、目标价、止损位或数值化涨跌概率；
- 免责声明必须明确说明结果不构成价格预测、交易或投资建议；
- 模型输出不能覆盖输入快照的指标、因子状态和研究版本。

## 12. 测试策略

### 单元测试

- 提示词包含快照中的真实数值、日期、规则状态和禁止事项；
- 校验器接受合法报告；
- 校验器拒绝缺字段、超长列表和越界金融内容；
- 服务首次调用模型并保存，重复调用不再调用模型；
- 快照不存在、模型失败或校验失败时不写数据库。

### 数据库测试

- V6 表、外键、`jsonb` 字段和唯一约束存在；
- 结构化列表可以完整写入和读取；
- 并发或重复保存最终只保留一条记录；
- 删除正式快照时禁止留下孤立解读记录。

### HTTP 测试

- 首次生成返回 `201`；
- 重复生成返回 `200`；
- 历史查询按时间倒序；
- `404`、`422`、`502`、`503` 使用稳定错误码。

### 真实模型验收

真实 GLM-4.7 调用不混入普通自动化测试。只有明确配置 API Key 时才手动执行，并使用数据库中的真实黄金研究快照验证结构、事实一致性和安全边界。

## 13. 学习分工

兵哥负责：

- `ResearchNarrativePromptBuilder` 的核心提示词；
- `ResearchNarrativeValidator` 的核心安全规则；
- 根据红灯测试解释自己的实现取舍。

Codex 负责：

- 领域骨架和可编译测试夹具；
- V6 迁移、JDBC 映射、Spring AI 结构化输出和 HTTP 接口；
- 测试审查、完整回归、真实模型验收和分任务提交推送。

新增生产类、`record`、异常、服务、控制器和配置类均添加简短中文类级 Javadoc；不常见实现增加必要的中文行内注释。

## 14. 验收标准

- 解读只能绑定数据库中的正式快照；
- 相同快照、模型和提示词版本重复调用不会产生第二次模型费用；
- 正式解读完整记录模型、提示词版本、提示词摘要和生成时间；
- 模型失败、格式错误或越界内容不会进入正式记录；
- API 不返回旧的通用聊天结构；
- 自动化测试不依赖真实模型网络；
- 手动验收结果不包含假新闻、价格预测、交易指令或投资建议；
- 提交不包含 API Key、数据库密码和现有无关工作区改动。
