# 黄金方向预测评测闭环设计

## 1. 目标

在现有真实黄金研究快照和大模型解读之上，建立可追踪、可评分、可比较的方向预测闭环，用真实后续价格回答“研究助手是否越来越准”。

本阶段属于研究评测，不是量化交易。系统不下单、不管理仓位、不计算交易收益，也不承诺历史准确率能够代表未来表现。

## 2. 核心原则

- 只使用数据库中已经正式留痕的黄金研究快照作为预测输入。
- 只使用主行情来源后续真实价格进行评分，不编造行情或补齐缺失日期。
- 预测创建后不可修改，防止看到结果后改写历史判断。
- 模型、提示词和预测规则都必须版本化，保证不同版本可以公平比较。
- 不输出具体目标价、止损位、仓位、买卖指令或数值化涨跌概率。
- 不根据单次预测结果自动修改提示词、规则或模型配置。

## 3. 范围

### 3.1 本阶段包含

- 为正式 `gold-multifactor-v2` 快照生成下一有效交易日三分类方向预测；
- 保存不可变预测记录及输入版本；
- 新的真实黄金价格出现后解析待验证预测；
- 保存实际涨跌幅、实际方向、是否命中和评分时间；
- 查询单条预测、历史预测和总体评测统计；
- 计算总体准确率、分类准确率、最近 20 条滚动准确率和简单基线表现；
- 使用真实数据完成一次前向预测，但不提前制造评分结果。

### 3.2 本阶段不包含

- 自动交易、模拟下单、仓位管理和止盈止损；
- 精确价格预测或涨跌概率；
- 使用后来数据批量生成伪历史预测；
- 新闻、社交媒体或未经留痕的自由文本输入；
- 自动调参、自动切换生产模型或自动发布新提示词版本；
- 收益曲线、最大回撤和夏普比率等交易策略指标。

## 4. 预测口径

### 4.1 基准价格

预测基准价格使用正式研究快照中的 `latestGoldDate` 和 `gold.currentPrice`。服务不得在生成预测时重新查询并覆盖快照内的价格。

### 4.2 目标日期

“下一有效交易日”不是下一个自然日，而是主行情来源在基准日期之后出现的第一条有效工作日黄金价格。

- 周六、周日记录不作为目标价格；
- 节假日不维护硬编码日历；
- 基准日期之后尚无有效工作日价格时，预测保持待验证；
- 目标日期只能在真实价格入库后确定，生成预测时保存为空；
- 主数据源缺失时不使用其他来源替换正式评分口径。

### 4.3 实际方向

实际涨跌幅计算公式：

```text
(目标价格 - 基准价格) / 基准价格 × 100
```

分类阈值固定为预测规则版本的一部分：

- 实际涨跌幅大于 `+0.5%`：`bullish`；
- 实际涨跌幅小于 `-0.5%`：`bearish`；
- 其余范围：`neutral`。

边界值 `+0.5%` 和 `-0.5%` 均归为 `neutral`。

Java 枚举常量使用 `BULLISH`、`NEUTRAL`、`BEARISH`，数据库值统一保存为小写。

## 5. 预测生成

### 5.1 专用模型合同

新增独立的预测网关，不复用普通聊天接口，也不让现有研究解读承担预测职责。预测模型只返回：

```json
{
  "direction": "bullish | neutral | bearish",
  "reasoning": "基于正式快照中双因子状态的简短研究依据",
  "invalidationConditions": [
    "哪些因子变化会使当前方向判断失效"
  ]
}
```

模型不返回概率、价格目标、仓位或交易建议。第一版模型继续使用 `glm-4.7`。

### 5.2 输入约束

预测提示词只包含：

- 正式快照编号、分析日期和各数据日期；
- 黄金基准价格和 1、5、20 期收益率；
- 实际利率变化、状态和确定性规则解释；
- 广义美元指数变化、状态和确定性规则解释；
- 固定的三分类定义和禁止项。

模型不得生成新闻、政策事件或提示词未提供的外部事实。

### 5.3 幂等键

同一输入只能产生一条相同版本预测：

```text
snapshot_id + model_name + prompt_version + forecast_rule_version
```

服务在调用模型前检查幂等记录，数据库唯一约束处理并发请求。重复请求直接返回已有预测，不重复产生模型费用。

第一版版本固定为：

- `prompt_version = gold-direction-forecast-prompt-v1`
- `forecast_rule_version = gold-next-session-direction-v1`

## 6. 预测状态

预测状态包括：

- `pending`：等待基准日期之后的真实有效工作日价格；
- `resolved`：已经保存真实结果和评分；
- `data_missing`：存在后续同步记录，但在允许观察窗口内仍无法获得有效价格；
- `voided`：仅用于明确的数据错误或版本作废，必须保存原因，不允许物理删除。

第一版自动流程只产生 `pending` 和 `resolved`。`data_missing` 与 `voided` 先保留领域合同，不开放任意修改接口。

## 7. 数据模型

新增 `gold_direction_forecast` 表，所有 SQL 关键字、表名和字段名使用小写。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | `uuid` | 预测主键 |
| `snapshot_id` | `uuid` | 正式研究快照外键 |
| `base_date` | `date` | 快照黄金基准日期 |
| `base_price` | `numeric(20,8)` | 快照黄金基准价格 |
| `predicted_direction` | `varchar(16)` | 模型预测方向 |
| `reasoning` | `text` | 预测依据 |
| `invalidation_conditions` | `jsonb` | 失效条件列表 |
| `model_name` | `varchar(100)` | 实际模型名称 |
| `prompt_version` | `varchar(64)` | 提示词版本 |
| `prompt_hash` | `char(64)` | 提示词 SHA-256 |
| `forecast_rule_version` | `varchar(64)` | 分类和目标规则版本 |
| `raw_response` | `text` | 模型原始响应，仅用于内部审计 |
| `status` | `varchar(16)` | 预测状态 |
| `target_date` | `date` | 实际目标工作日，待验证时为空 |
| `target_price` | `numeric(20,8)` | 真实目标价格，待验证时为空 |
| `actual_return` | `numeric(12,6)` | 真实涨跌幅百分比 |
| `actual_direction` | `varchar(16)` | 按同一阈值计算的实际方向 |
| `hit` | `boolean` | 预测方向是否命中 |
| `resolved_at` | `timestamptz` | 评分时间 |
| `created_at` | `timestamptz` | 预测生成时间 |

不保存完整提示词。模型原始响应是否留痕延续上一阶段策略：保存在数据库中用于审计，但不通过 HTTP 返回。

预测记录和正式快照均不可级联删除。

## 8. 到期解析

`GoldForecastResolutionService` 只处理 `pending` 预测：

1. 查询 `base_date` 之后按日期升序排列的真实黄金价格；
2. 排除周六和周日；
3. 取第一条有效工作日价格作为目标价格；
4. 没有目标价格时保持 `pending`，不写空评分；
5. 使用预测记录中冻结的基准价格计算真实涨跌幅；
6. 使用记录绑定的规则版本计算实际方向；
7. 比较预测方向并保存 `hit`；
8. 已经 `resolved` 的记录再次处理时保持不变。

解析服务不调用大模型，结果完全由真实价格和确定性 Java 规则产生。

## 9. 评测指标

统计只包含 `resolved` 预测：

- 总预测数；
- 待验证数；
- 已验证数；
- 总体准确率；
- `bullish`、`neutral`、`bearish` 各自样本数和准确率；
- 最近 20 条已验证预测的滚动准确率；
- 按模型名、提示词版本和预测规则版本分组的表现；
- “始终预测 neutral”的简单基线准确率。

当已验证样本为 0 时，准确率返回空值，不返回 `0%`，避免把“没有证据”误解为“表现为零”。

第一阶段不设置“合格准确率”，也不因为小样本领先基线就宣布模型有效。接口必须同时返回样本数。

## 10. HTTP 合同

### 10.1 生成或读取预测

```http
post /api/research/gold/snapshots/{snapshotId}/forecasts
```

- 首次创建返回 `201` 和 `created=true`；
- 幂等命中返回 `200` 和 `created=false`；
- 快照不存在返回 `404`；
- 模型不可用、响应非法或预测越界沿用稳定的专用错误码。

### 10.2 查询预测历史

```http
get /api/research/gold/forecasts
```

支持按状态、模型版本和数量限制查询，默认按创建时间倒序。

### 10.3 解析待验证预测

```http
post /api/research/gold/forecasts/resolve
```

该接口只触发确定性评分，不调用模型。返回扫描数、成功解析数和仍待验证数。

### 10.4 查询评测统计

```http
get /api/research/gold/forecasts/evaluation
```

返回样本数、总体准确率、分类准确率、滚动准确率和中性基线结果。

## 11. 失败处理

| 场景 | HTTP | 行为 |
|---|---:|---|
| 正式快照不存在 | 404 | 不调用模型、不保存 |
| 快照不是双因子正式版本 | 422 | 拒绝生成预测 |
| 模型不可用 | 503 | 不保存正式预测 |
| 模型 JSON 无法解析 | 502 | 不保存正式预测 |
| 预测包含概率、价格或交易建议 | 422 | 不保存正式预测 |
| 后续真实价格尚未出现 | 200 | 保持 `pending` |
| 重复解析已完成预测 | 200 | 返回已有结果，不覆盖 |
| 数据库并发重复 | 200 | 返回唯一约束最终保留记录 |

## 12. 测试策略

### 12.1 单元测试

- 提示词只包含正式快照事实和三分类定义；
- 模型响应只能使用三个合法方向；
- 禁止概率、目标价、仓位和交易建议；
- 服务幂等命中时不调用模型；
- 模型或校验失败时不保存；
- `+0.5%`、`-0.5%` 边界归为 `neutral`；
- 周末价格被排除，节假日由下一条真实有效工作日记录决定；
- 没有后续价格时保持 `pending`。

### 12.2 数据库测试

- 表结构、外键、状态约束和唯一键存在；
- `jsonb` 失效条件完整往返；
- 重复保存不覆盖第一次预测；
- 已解析记录不能被再次覆盖；
- 删除正式快照时外键阻止产生孤立预测。

### 12.3 HTTP 测试

- 首次和重复生成分别返回 `201` 与 `200`；
- 响应不暴露完整提示词和原始模型响应；
- 解析接口不调用模型；
- 评测无样本时准确率为空；
- 稳定错误码覆盖 `404`、`422`、`502`、`503`。

### 12.4 真实验收

- 使用数据库中最新正式双因子快照生成一条真实 `pending` 预测；
- 重复生成验证不再次调用模型；
- 不编造目标价格，不提前将预测标记为命中或失败；
- 等主行情来源出现下一有效工作日价格后，再运行解析并形成第一条真实评分。

## 13. 学习分工

兵哥负责：

- 实现三分类阈值规则和边界值；
- 实现下一有效工作日选择规则；
- 根据红灯测试解释为什么周末、缺失数据和边界值这样处理。

Codex 负责：

- 领域合同、可编译红灯夹具和中文注释；
- Spring AI 专用预测网关、数据库迁移、JDBC、HTTP 和统计查询；
- 代码审查、全量回归、真实预测验收、分任务提交与推送。

所有新增生产类、`record`、枚举、异常、服务、控制器和配置类必须添加简短中文类级 Javadoc。不常见的实现只添加必要中文注释，避免教程式长注释。

## 14. 完成标准

- 预测只能由正式双因子快照产生；
- 相同幂等键不会重复调用模型；
- 预测创建后不可修改核心判断；
- 评分完全由真实后续价格和版本化 Java 规则产生；
- 周末、缺失数据和阈值边界具有自动化测试；
- 统计结果同时返回准确率和样本数，并包含中性基线；
- HTTP 不暴露 API Key、完整提示词或模型原始响应；
- 全量自动化测试通过；
- 至少生成一条真实待验证预测，不伪造评分结果；
- Git 提交不包含密钥、数据库密码或无关未完成文件。
