# 黄金方向预测历史回测设计

## 1. 目标

使用数据库中已有的真实黄金价格、美国 10 年期实际利率和美元指数历史数据，重建过去交易日的研究快照，并使用当前正式模型、提示词和方向规则生成历史预测。系统随后使用下一有效交易日的真实黄金价格结算预测，快速形成可评测样本。

回测用于初步验证预测流程和提示词，不替代上线后的实时验证。所有回测结果必须与实时预测分开存储、分开统计、分开展示。

## 2. 数据现状

本地 PostgreSQL 当前拥有足够的真实历史数据：

- `xauusd` 黄金价格：3976 条，覆盖 2011-06-01 至 2026-08-26。
- `dfii10` 美国 10 年期实际利率：5916 条，覆盖 2003-01-02 至 2026-08-25。
- `dtwexbgs` 广义美元指数：5174 条，覆盖 2006-01-02 至 2026-08-21。

回测只读取数据库中的真实记录，不生成假行情、假宏观数据或假新闻。

## 3. 核心约束

### 3.1 防止未来数据泄漏

回测日期为 `T` 时，研究快照只能读取日期不晚于 `T` 的数据。`T` 之后的数据只能用于结算预测，不能进入输入指标、研究解释或模型提示词。

每个历史快照仍按正式规则计算黄金 1、5、20 期收益率、实际利率变化、美元指数变化和因子状态。

### 3.2 回测与实时隔离

回测不得写入实时使用的 `gold_research_snapshot`、`gold_research_narrative` 和 `gold_direction_forecast` 表，避免影响最新日报、实时命中率和幂等判断。

回测使用独立任务表和独立明细表。实时评测接口只统计实时预测；回测评测接口只统计指定回测任务。

### 3.3 模型和版本固定

一项回测任务创建后固定以下信息：

- 模型名称；
- 预测提示词版本；
- 方向规则版本；
- 回测日期范围；
- 计划样本数。

任务执行期间配置变化不能改变已经创建的任务。不同版本必须创建不同任务，不能覆盖旧结果。

### 3.4 外部调用边界

创建回测任务不会立即批量调用模型。只有显式启动任务才允许调用 GLM，并在启动前提示预计调用次数。

默认计划样本数为 60，允许范围为 1 至 120。每完成一条预测立即保存，任务中断后从未完成日期继续，已成功日期不得重复调用模型。

## 4. 数据模型

### 4.1 回测任务

任务记录保存：

- 任务编号；
- 起止日期；
- 计划样本数；
- 模型、提示词和规则版本；
- 状态：`created`、`running`、`completed`、`failed`；
- 已完成数、命中数、失败数；
- 最近错误摘要；
- 创建、开始和完成时间。

### 4.2 回测明细

每条明细保存：

- 任务编号和回测日期；
- 当日三个数据源的实际日期；
- 构建预测所需的完整指标和因子状态；
- 基准黄金价格；
- 模型预测方向、依据和失效条件；
- 下一有效交易日及其真实价格；
- 真实涨跌幅、真实方向和是否命中；
- 模型、提示词、规则版本和提示词摘要；
- 原始模型响应，仅供内部审计，不通过公开接口返回；
- 创建时间。

任务编号和回测日期组成唯一约束，保证恢复执行时不会重复生成。

## 5. 执行流程

1. 创建任务并冻结配置版本。
2. 从真实黄金价格中选择最近若干个可结算交易日。
3. 对每个日期按“截至该日”的边界读取三类历史数据。
4. 重建确定性研究快照，不写入实时快照表。
5. 构建正式黄金方向预测提示词并调用 GLM。
6. 校验模型结构化响应和安全边界。
7. 查找下一有效交易日黄金价格并结算方向。
8. 在同一事务中保存明细并更新任务计数。
9. 单条失败时记录错误并继续后续日期；系统级错误时任务标记为 `failed`。
10. 所有计划日期处理结束后任务标记为 `completed`。

## 6. 接口

### 6.1 创建任务

`post /api/research/gold/backtests`

接收计划样本数，默认 60。返回任务信息和预计模型调用次数，不触发 GLM。

### 6.2 启动或继续任务

`post /api/research/gold/backtests/{id}/run`

后台执行未完成日期，立即返回 `202 accepted`。重复请求同一运行中任务不会创建第二个执行器。

### 6.3 查询任务状态

`get /api/research/gold/backtests/{id}`

返回状态、进度、命中数、失败数和最近错误，不返回模型原始响应。

### 6.4 查询回测结果

`get /api/research/gold/backtests/{id}/results?limit=60`

按回测日期倒序返回已完成明细。

### 6.5 查询回测评测

`get /api/research/gold/backtests/{id}/evaluation`

返回样本数、总体命中率、最近 20 条命中率、方向表现和中性基线。响应必须明确标记 `BACKTEST`，不能与实时评测混淆。

## 7. 后台执行与恢复

回测使用独立、受限的后台执行器，默认单线程顺序调用模型，避免触发限流。任务级状态更新使用数据库条件更新，阻止同一任务并发运行。

应用异常退出后，`running` 任务不会自动调用模型。用户再次显式请求运行时，系统根据已保存明细继续未完成日期。

## 8. 错误处理

- 历史共同数据不足：该日期记为失败，不生成预测。
- 下一交易日价格不存在：跳过该日期，不计入可结算样本。
- 模型暂时不可用：记录安全错误摘要，停止当前任务，允许后续继续。
- 模型 JSON 非法或违反安全规则：该日期记为失败，继续下一日期。
- 任务不存在：返回 404。
- 样本数越界或日期非法：返回 400。
- 重复启动运行中任务：返回当前任务状态，不重复执行。

公开错误和日志均不得包含 API Key、完整提示词或模型原始响应。

## 9. 可信度说明

历史宏观数据可能在发布后被修订，当前数据库中的旧值不一定等于当时首次发布值。因此回测结果应标记为“使用当前可获得历史版本”，可能比真实实时运行略乐观。

回测达到 30 条后可以启用 AI 复盘，但页面和接口必须继续分别展示回测与实时样本。任何回测命中率都不构成未来收益承诺或投资建议。

## 10. 测试与验收

- 证明日期 `T` 的输入不包含 `T` 之后的数据。
- 证明结算价格来自下一有效交易日，而不是自然日简单加一天。
- 证明回测不会写入或影响实时三张业务表。
- 证明相同任务和日期不会重复调用模型或重复保存。
- 证明中断后能从未完成日期继续。
- 证明回测统计与实时统计完全隔离。
- 证明原始模型响应不会出现在公开 API 或日志中。
- 使用伪模型完成自动化测试，不在普通测试中产生真实费用。
- 真正批量调用 GLM 必须由兵哥单独确认。

## 11. 暂不包含

- 分钟级或日内预测；
- 自动修改正式预测提示词；
- 使用回测结果冒充实时成绩；
- 自动交易、开仓、仓位或止损建议；
- 在本阶段实现可视化面板。

完成回测 API 后，再单独设计只读可视化面板。
