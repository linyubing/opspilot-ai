# 黄金回测可视化页面设计

## 目标

为个人学习和研究提供一个本地浏览器页面，将黄金历史回测的评估接口转换为直观的中文结果。页面只负责展示已经计算完成的回测指标，不创建任务、不运行回测、不调用大模型，也不给出开仓建议。

## 使用方式

- 页面地址：`http://localhost:8080/backtest.html`
- 用户可以输入回测任务 ID 后加载结果。
- 页面支持通过 `?id=<任务ID>` 自动加载，方便保存和再次打开。
- 数据来自现有接口：`get /api/research/gold/backtests/{id}/evaluation`。

## 技术方案

页面放在 Spring Boot 的 `src/main/resources/static` 目录，由现有应用直接提供静态资源。使用原生 HTML、CSS 和 JavaScript，不增加 React、Node.js、Thymeleaf、WebJars或图表库。

选择该方案的原因：

- 当前只有一个本地展示页面，不需要独立前端工程。
- 启动后端即可访问，学习和迁移成本低。
- 不增加构建链、依赖下载和跨域配置。
- 后续若页面数量和交互明显增加，再单独评估前端工程化。

## 页面结构

### 查询区

- 页面标题：黄金回测评估
- 回测任务 ID 输入框
- “加载评估”按钮
- 当前任务 ID 和加载状态

### 中文结论

突出展示接口返回的 `conclusion.level` 和 `conclusion.summary`。页面将等级翻译为中文：

- `INSUFFICIENT`：样本不足
- `NO_EDGE`：未发现优势
- `UNBALANCED`：方向表现失衡
- `WEAK`：优势较弱
- `PROMISING`：值得继续验证

结论必须保持谨慎措辞，不转换为交易建议。

### 核心指标

使用独立卡片展示：

- 有效样本数
- 总体准确率
- 最近 20 条准确率
- 多数类别基线
- 相对基线提升值
- 平衡准确率

比例统一显示为百分比并保留两位小数。空值显示为“暂无数据”，不能显示 `null`、`NaN` 或虚构数字。

### 混淆矩阵

使用三行三列的表格展示真实方向与预测方向：

- 行表示真实方向。
- 列表示预测方向。
- 对角线表示预测正确的数量。
- 表格旁提供一句中文阅读说明，避免误解行列含义。

### 分方向表现

分别展示模型预测上涨、中性、下跌时的样本数、命中数和准确率，数据沿用现有 `bullish`、`neutral`、`bearish` 字段。

## 视觉设计

- 使用浅色背景、深色正文和低饱和金色强调色。
- 结论卡片是页面最强视觉层级，指标卡片次之。
- 上涨、中性、下跌分别使用克制的绿、灰、红标识。
- 桌面端使用多列布局，窄屏自动改为单列。
- 不使用装饰性动画，加载状态只提供必要反馈。

## 数据流

1. 用户打开页面。
2. JavaScript 从 URL 查询参数读取可选任务 ID。
3. 用户点击加载，或页面根据查询参数自动加载。
4. 浏览器请求现有评估接口。
5. 请求成功后渲染结论、指标、矩阵和分方向数据。
6. 请求失败时保留查询区，并显示中文错误信息。

页面不在浏览器持久化回测数据，不修改服务端状态。

## 错误处理

- 任务 ID 为空：提示“请输入回测任务 ID”。
- 任务 ID 格式错误：提示“任务 ID 格式不正确”。
- 任务不存在：显示后端返回的中文错误；无法解析时显示“未找到该回测任务”。
- 后端未启动或网络失败：显示“无法连接后端服务，请确认应用已经启动”。
- 接口缺少部分指标：对应位置显示“暂无数据”，其余内容继续展示。
- 连续点击加载时禁用按钮，防止重复请求。

## 安全边界

- 页面不接收或显示 API Key。
- 页面不展示回测原始大模型响应。
- 页面只访问同源只读评估接口。
- 页面不包含买入、卖出、仓位或收益承诺。

## 测试与验收

### 自动测试

- Spring MVC 能够返回 `backtest.html`。
- 页面入口的媒体类型为 HTML。
- 现有评估接口测试继续通过。
- 全部非 Live 测试继续通过。

### 浏览器验收

- 以已有回测任务 ID 打开页面可以看到中文结论。
- 六个核心指标能正确转换为百分比。
- 混淆矩阵行列与接口数据一致。
- 无效任务 ID 显示中文错误。
- 桌面宽度和窄屏宽度均无横向溢出。
- 浏览器控制台没有 JavaScript 错误。

## 不在本次范围

- K 线图、收益曲线和交易模拟
- 用户登录和权限系统
- 独立前端工程或部署
- 使用大模型生成页面结论
