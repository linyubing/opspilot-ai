# 黄金实验历史版本输入

目标：让正式实验构建链路只使用当时已公开的宏观版本，随后才能可信地判断预测能力是否改善。本次不宣称准确率提升，不替换 GLM 正式预测，不读取最终留出集评分。

兵哥已要求按推荐方案持续推进、不要反复确认；本次由当前会话直接实现，继续使用原工作目录，保留用户文件。

## 设计

- 使用已验证的 FRED `output_type=1` JSON 归档。配置 `opspilot.forecast.gold.history-dir` 指向 D 盘目录，默认空，未配置时仅实验构建明确报错，不阻止应用启动。
- 每次 build 读取两个完整文件，生成不可变批次；一次实验中的所有日期、特征组共享同一份输入。文件 SHA-256、版本策略、覆盖区间进入数据集和实验参数。
- 预测基准日 D 只允许使用 D-1 已生效且未失效的版本，包含区间两端。观测日也必须不晚于 D-1。点号保留为缺失，不能回退旧版本。
- 校验序列、类型、条数、区间边界、分批完整性、重复/重叠、数字合法性。早于最早版本可跳过；超出归档末端必须报过期错误，不能截短实验后冒充最新。
- `GoldResearchSnapshotService` 增加显式输入重载，复用全部计算公式；现有实时和旧历史查询接口不在本次静默改变。`GoldDatasetBuilder` 默认只走归档重载。
- 已有实验不删除、不改写。新实验保存 `macroInput`，无此字段的历史记录解释为旧口径；数据集指纹包含来源策略，避免同数值但不同证据的实验混淆。
- 归档是可迁移的磁盘数据，不放 Maven target，不进 Git；保留已提交真实研究归档供独立对照。采集工具必须显式指定末端，拒绝覆盖既有目录，失败不发布半个批次。

## 验收

1. 回归测试复现周发布延迟、版本修订、缺失值、不完整文件和过期末端。
2. 完整 builder 测试证明最新值仓库不参与实验输入，修改晚到版本不会改变较早日期样本。
3. 参数与指纹保留可复现来源，旧数据明确不属于新口径。
4. 用既有真实归档重建截至 2024-11-08 的样本，与上一轮 1500 条样本全部 36 项特征、标签、日期逐一一致；不重新选择日期、不评分留出集。
5. 全量测试、审查、Git 提交推送。训练收敛和未来准确率是后续工作，不以本批代码完成替代总目标。
