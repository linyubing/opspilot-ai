# 黄金投资研究助手设计规格

## 1. 背景与目标

现有项目已经具备 Spring AI 对话、文档解析、向量切片、PGVector 持久化和知识库文档幂等上传能力。后续产品方向从“运维助手”调整为个人使用的“黄金投资研究助手”。

第一版聚焦黄金，不扩展石油，不连接券商，不执行真实或模拟交易。系统使用真实行情、真实宏观数据和可追溯的研究资料，生成中文黄金研究简报，支持基于资料的追问，并持续评估“下一有效交易日方向预测”的历史表现。

项目的学习重点是 AI 应用工程：结构化数据接入、确定性指标计算、RAG 证据检索、大模型结构化生成、预测评估和可观测性，而不是普通 CRUD。

## 2. 产品边界

### 2.1 第一版包含

- 个人单用户模式，不开发注册、登录和权限系统。
- XAU/USD 最新价格与日线历史数据，统一使用美元/盎司口径。
- 美元、实际利率、通胀等宏观时间序列。
- 公开且可追溯的官方信息，以及用户上传的 PDF、Word、TXT 研报和笔记。
- 手动触发当日黄金研究简报。
- 基于行情、宏观数据和研究资料的追问问答。
- 下一有效交易日的看多、震荡、看空方向预测。
- 预测到期后的自动评分、历史表现统计和版本对比。

### 2.2 第一版不包含

- 真实下单、模拟交易、仓位管理、交易流水、回测交易策略。
- 明确的买入或卖出指令、收益承诺和精确目标价预测。
- 分钟级或逐笔实时行情。
- 石油及其他资产。
- 多用户、通知推送和定时生成简报。
- 自动根据单次预测结果修改生产规则或提示词。

## 3. 核心原则

1. Java 负责数据、指标、规则和校验，大模型负责归纳、解释和表达。
2. 每项市场事实必须来自结构化数据或可追溯资料，大模型不得补造事实。
3. 每份简报必须展示数据截至时间和引用来源。
4. 关键数据缺失或过期时宁可不生成，也不使用虚构数据补齐。
5. 预测生成后不可修改；改进通过创建新分析版本完成。
6. 所有内容仅用于个人研究，不构成投资建议。

## 4. 总体架构

系统采用“结构化分析引擎 + RAG + 大模型总结”架构，分为五个业务模块。

### 4.1 `marketdata` 行情与宏观数据

负责调用外部数据源、统一时间和单位、保存原始观测值，并向上层提供稳定的领域接口。外部供应商位于适配器层，更换供应商时不影响分析模块。

### 4.2 `research` 研究资料

复用现有 Tika 文档解析、向量切片和 PGVector 能力，统一管理用户上传资料和公开信息。每份资料必须保存标题、来源、发布时间、采集时间和原文地址；无法确认来源的资料不参与正式简报。

### 4.3 `analysis` 确定性分析

使用 Java 计算价格和宏观指标，不调用大模型。第一版计算：

- 1 日、5 日、20 日和 60 日涨跌幅；
- 20 日和 60 日均线；
- 20 日波动率；
- 近 20 日和近 120 日高低点；
- 美元、实际利率和通胀指标的近期变化方向。

指标只作为研究依据，不自动转换成交易信号。

### 4.4 `briefing` 简报生成

组织确定性指标和 RAG 证据，调用大模型生成结构化中文简报，执行引用、时间和字段完整性校验，并保存正式结果。

### 4.5 `chat` 研究问答

围绕历史简报、结构化数据和知识库资料回答追问。回答缺少可靠依据时必须明确说明“证据不足”，不能仅凭模型常识生成市场结论。

## 5. 数据来源

### 5.1 黄金行情

第一数据源采用 Alpha Vantage：

- `GOLD_SILVER_SPOT` 获取黄金现货价格；
- `GOLD_SILVER_HISTORY` 获取黄金日线历史价格；
- 标的使用 `XAU`，计价统一为 USD/盎司。

系统保存供应商、供应商时间、采集时间和数据完整性状态。第一版以同一供应商的完整日线作为预测生成和评分口径，不混用其他平台的收盘价。

官方文档：https://www.alphavantage.co/documentation/

### 5.2 宏观数据

第一数据源采用美国圣路易斯联储 FRED API，通过时间序列观测接口获取美元、实际利率和通胀相关序列。具体序列代码由配置管理，每条记录保留序列代码、单位、观测日期、发布时间和采集时间。

官方文档：https://fred.stlouisfed.org/docs/api/fred/series_observations.html

### 5.3 新闻与研究资料

- 自动来源只允许接入具有公开 API、RSS 或明确公开发布渠道的官方信息。
- 初始范围包括美联储、美国官方通胀发布渠道和世界黄金协会公开内容。
- 不绕过付费墙，不抓取登录后内容，不复制来源不明的二手消息。
- 用户可以继续上传拥有使用权限的研报、PDF 和个人笔记。
- 每个自动来源必须在启用前确认使用条款；未确认的来源保持禁用，不使用网页爬虫兜底。

## 6. 核心数据模型

### 6.1 `market_price`

保存标的、交易日期、开高低收、币种、计量单位、供应商、供应商时间和采集时间。标的与交易日期在同一供应商内唯一。

### 6.2 `macro_observation`

保存指标代码、观测日期、数值、单位、发布时间、供应商和采集时间。指标代码与观测日期唯一。

### 6.3 `research_material`

保存资料标题、正文、类型、来源、发布时间、原文地址、内容哈希和处理状态。现有知识库文档及向量切片关系继续复用，避免重复解析和重复入库。

### 6.4 `daily_briefing`

保存简报日期、数据截止日期、市场状态、主要驱动、技术状态、三种情景、风险、观察项、引用、模型版本、提示词版本和生成状态。

### 6.5 `market_forecast`

保存生成时间、数据日期、目标日期、预测方向、置信度、主要依据、失效条件、分析版本、验证状态、实际方向、实际涨跌幅和评分时间。

预测状态包括：`pending`、`resolved`、`data_missing`、`voided`。枚举常量遵循 Java 规范使用大写，数据库值统一使用小写。

## 7. 简报生成流程

1. 手动发起简报生成。
2. 同步或读取最新黄金日线和宏观观测值。
3. 检查关键数据是否完整、是否超过允许的新鲜度。
4. Java 计算价格指标和宏观变化方向。
5. 按黄金价格、美元、实际利率、通胀、央行购金和地缘风险等主题检索研究证据。
6. 将结构化指标、证据、数据时间和固定输出约束交给大模型。
7. 校验结构化结果、引用真实性和字段完整性。
8. 保存正式简报和不可修改的方向预测。

简报固定包含：

- 数据截至时间；
- 市场概况；
- 当前主要驱动因素；
- 技术状态；
- 看多、基准、看空三种情景；
- 每种情景的触发条件和失效条件；
- 当前风险和后续观察项；
- 引用来源；
- “仅供研究，不构成投资建议”的声明。

不输出缺少依据的上涨概率，也不为了填满格式强行给出结论。

## 8. 下一有效交易日预测

### 8.1 预测目标

以生成简报时使用的最后一根完整日线收盘价为基准，预测下一根有效完整日线的方向：

- 实际涨幅大于 `+0.5%`：`bullish`；
- 实际跌幅小于 `-0.5%`：`bearish`；
- 介于 `-0.5%` 到 `+0.5%`：`neutral`。

第一版预测方向和低、中、高三级置信度，不预测精确价格。

### 8.2 周末和节假日

“下一日”指下一根由主数据源提供的完整日线，不是下一个自然日：

- 周末和无行情的节假日不参与期限计算；
- 周五预测通常等待下周一完整日线；休市时继续顺延；
- 周末手动生成时使用最近一个完整交易日的数据；
- 目标日没有完整收盘数据时，预测保持 `pending`；
- 系统不靠工作日规则推测是否开市，以主数据源的完整日线为准。

### 8.3 评分与统计

下一根完整日线出现后，系统计算真实涨跌幅和实际分类，并保存：

- 是否命中；
- 实际涨跌幅；
- 预测置信度；
- 错误类型；
- 使用的分析版本。

统计范围包括总预测次数、已验证次数、总体准确率、三类各自准确率、最近 20 次滚动准确率、不同置信度命中率，以及与“始终预测震荡”等简单基线的比较。

## 9. 持续改进机制

系统不会在生产环境中根据单次结果自行修改提示词或规则。改进流程为：

1. 积累不可修改的预测和评分记录；
2. 按市场环境、预测方向、置信度和错误类型分析失败样本；
3. 修改因子、检索策略或提示词，并创建新的分析版本；
4. 使用相同历史区间进行滚动验证，避免使用未来信息；
5. 比较新旧版本及简单基线；
6. 只有新版本在未参与调整的验证区间表现更稳定时，才启用为生产版本。

系统目标是建立可衡量、可复现的改进过程，不承诺准确率持续提高，也不把历史回测表现描述为未来收益保证。

## 10. 异常与降级处理

- 行情或宏观数据缺失、过期：返回缺失项，不生成正式简报。
- 外部接口限流、超时：保留已有数据并记录可重试失败，不将旧数据标记为最新。
- 研究证据不足：对应结论明确标记“证据不足”。
- 大模型输出格式错误：自动重试一次，仍失败则保存失败记录。
- 引用不存在或无法关联资料：简报校验失败，不保存为正式版本。
- 下一根完整日线未产生：预测保持待验证，不提前评分。
- 主数据源不可用：停止正式评分；备用来源只用于诊断，不改变历史口径。
- API Key、数据库密码和模型配置只通过环境变量或本地未跟踪配置提供。

## 11. 测试策略

项目不编造假行情、假新闻或假研报。

### 11.1 指标单元测试

使用明确标注的数学输入验证涨跌幅、均线、波动率、方向分类和评分公式。这些数字只用于公式验证，不冒充真实市场数据。

### 11.2 外部适配器测试

使用 Alpha Vantage、FRED 等平台真实返回并脱敏后的响应快照，记录来源和采集时间，验证 JSON 解析、字段转换、空值和异常响应。

### 11.3 PostgreSQL 集成测试

将真实响应快照导入测试数据库，验证保存、幂等更新、查询、唯一约束、预测不可修改和评分状态流转。

### 11.4 真实端到端验收

单独执行真实接口验收：

`真实行情 → 真实宏观数据 → 真实新闻或研报 → 指标计算 → RAG 检索 → 真实模型生成简报 → 保存预测 → 下一有效交易日真实收盘价评分`

真实接口测试不加入默认 `mvn test`，避免网络波动、额度限制和外部服务故障导致普通构建随机失败。普通构建验证确定性逻辑和真实响应契约；发布前必须执行一次真实端到端验收。

## 12. 第一版验收标准

- 能同步并保存真实 XAU/USD 最新价格和日线数据。
- 能同步并保存指定的真实宏观时间序列。
- 能管理可追溯的公开资料和用户上传资料。
- 能手动生成带数据时间、证据引用和风险声明的中文黄金简报。
- 能基于简报、结构化数据和资料继续追问。
- 能生成不可修改的下一有效交易日方向预测。
- 下一根完整日线出现后能按统一口径评分。
- 能查看历史简报、历史预测、滚动准确率和版本表现。
- 关键数据或证据缺失时不会生成虚构结论。
- 不包含交易、下单、持仓、登录、通知和石油分析功能。

## 13. 现有代码处理

- 保留并复用文档解析、内容哈希、向量切片、PGVector 和 Spring AI 接入能力。
- 将现有知识库定位从运维文档调整为通用研究资料，不进行与新方向无关的大规模重构。
- 已暂停且未提交的文档生命周期代码不纳入本设计提交；实施时根据研究资料模块需要重新评估，不直接沿用旧流程。
- 后续按独立阶段实施真实数据接入、指标分析、简报生成、预测评分和历史统计，每个阶段都需通过测试、差异检查后再提交。
