# Twelve Data 已结束交易日合同核实

## 目的与本轮结论

代码基线：`894116fccfb4420cc8c271653a17c64df000937a`。
上一轮阻止未来日期/未来采集时间结算，但尚未判断供应商日线是否结束。
本轮不猜纽约、UTC 或悉尼的收盘钟点，而是核查供应商明确提供的闭市日参数。

找到一个可以继续实现和验证的合同：`GET /quote?symbol=XAU/USD&eod=true`。
官方 `/quote` 文档描述 `eod=true` 返回已结束交易日数据；本轮真实请求的已结束日期及四个 OHLC 字段与普通日线对应记录精确一致。
这不是所有发布边界的验证，不是生产改动，也不是准确率提升。

## 官方说明核实

- [官方 API 文档](https://twelvedata.com/docs/markets/market-state)：直接取正文 `/quote` 参数段，`eod` 默认为 false，true 要求闭市日数据。不是 `/eod` 端点的同名参数，也不是用 `is_market_open` 推导日线结束。
- 同一正文 `/time_series` 参数段说明日线忽略 `timezone` 参数，采用交易所本地时间；响应字段 `datetime` 表示蜡烛开始的日期/时刻。因此添加 `timezone=UTC` 并不能证明日线改为 UTC 收盘。
- [时区说明](https://support.twelvedata.com/en/articles/5745849-timezones) 列出 Forex 默认 Australia/Sydney，但本轮 XAU/USD 响应类型是 Precious Metal，不能不经核实直接套用普通外汇规则。
- [品种目录说明](https://support.twelvedata.com/en/articles/5620513-how-to-find-all-available-symbols-at-twelve-data) 区分外汇与大宗商品/贵金属目录。目录更新时间不是蜡烛收盘时刻。

网页工具无法打开巨大 API 正文（超过长度限制），因此使用 Node fetch 直接取得 HTTPS 官方正文并在本地提取对应章节；不是仅引用搜索摘要。

## 四次真实请求结果

均为 2026-10-03 的实际 HTTPS 请求，读取已有环境变量，不打印 Key 或带密钥 URL。每次只请求一个品种，没有循环重试。
原始响应保留在被 Git 忽略的 `backend/target`，没有写入生产行情/预测表，也没有公布价格。

| 请求 | 获取时刻 UTC | 返回日期 | 观察 |
|---|---|---|---|
| `/time_series`，1day，outputsize=3 | 12:23:35.813 | 10-03、10-02、10-01 | 包含周六；没有时区、完成状态字段 |
| `/eod`，不指定日期 | 12:25:24.359 | 10-02 | close 与普通日线 10-02 精确相同 |
| `/eod`，date=2026-10-03 | 12:27:22.300 | 10-03 | 也返回 close，但不同于较早普通日线 10-03 值 |
| `/quote`，eod=true | 12:29:50.184 | 10-02 | open/high/low/close 与普通日线 10-02 全部精确相同 |

差异请求相隔数分钟，不同字段值本身不能唯一证明盘中变化、修订、聚合差异或供应商错误。本轮不虚构价格差异原因。

`/eod` 两次响应的 timestamp 分别映射到当天 12:25 与 12:27 UTC，接近请求时刻，即使第一次 datetime 是前一天。因此不能把 timestamp 直接当作那个交易日的收盘时刻。
`/quote?eod=true` 的 `is_market_open` 为 true，但返回日期仍是 10-02；该字段反映的市场状态不能代替某根蜡烛是否已结束的合同。

## 下一轮实现与验收依据

推荐采用供应商显式 closed-day quote，而不是硬编码收盘时区或仅依赖 `/eod` 名称：

1. 固定请求 `eod=true`，校验标的、日期、完整且有效的 OHLC 与响应状态。
2. 用确认日期作为日线可用边界，且要求普通日线中该日期四个字段与确认响应精确一致。
3. 缺失、格式错误、未来日期、跨响应不一致时不能补值或默认已结束；不将当前行情悄悄当正式目标。
4. 确认来源、获取时刻和使用边界必须可追溯；既有未带确认依据的数据库记录不能自动获得确认标记。
5. 同步、快照、结算应共享确认依据，避免只有同步过滤、结算仍读取旧盘中记录。
6. 测试覆盖参数实际传递、字段不一致、确认缺失、零/非有限价格、UTC/纽约跨日、周末和发布切换；合同是供应商日期，不通过本地节假日日历篡改它。
7. 事前预测还需确认生成时刻早于目标结束；不能用晚生成的结果冒充样本外预测。

本轮四次网络请求证实该接口在这一次周末观察中可用；工作日发布切换、异常响应、未来日期的完整合同仍需实现级测试和后续真实观察。
本轮没有修改 Java、SQL、模型、方向门槛或最终留出集，没有启动服务或重跑 Maven；不能引用上一轮测试数量作为本轮运行证明。

路线评估：明确拒绝“看到 close 字段或接口名含 EOD 就认定收盘”的快捷路线；继续实现显式合同后再评测新预测。修复评测口径不等于黄金方向已经具备可预测增益。
