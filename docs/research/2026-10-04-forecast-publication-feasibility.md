# 次日黄金预测：发布时间可行性与路线复盘

## 本轮结论

连续工作日里，按现有候选规则，上一个日线时段的结束与下一个时段的开始是同一绝对时刻。因此，要求同时满足“使用已结束的上一日完整OHLC”和“在下一完整时段开始前完成模型调用”，没有正的生成时间窗口。不能直接把这个截止条件加到正式链路，再把所有工作日不能预测说成修复成功。

该结论是候选时段下的可行性分析，不是供应商官方时段合同。它改变下一步实施方向：先明确并记录真实发布时刻和输入可得性，保留次日收盘相对基准收盘的方向目标；不能无提示地改为两日收益、盘中剩余收益或只保留周末样本。

本轮没有提高模型准确率，没有训练或读取最终留出集，也没有生成、结算或修改正式预测。

### 可复现只读查询

下列SQL不含连接凭据，关键字统一小写。它复现上述六个区间，不计算模型分数或读取留出样本标签。

```sql
begin read only;
with recent as (
    select price_date, collected_at,
           case extract(isodow from price_date)::int
               when 5 then price_date + 3
               when 6 then price_date + 2
               else price_date + 1
           end as target_date
    from gold_daily_bar
    where provider = 'twelve_data' and symbol = 'XAUUSD'
      and price_date between date '2026-09-25' and date '2026-10-02'
), boundaries as (
    select *,
           ((price_date + 1) + time '07:00')
               at time zone 'Australia/Sydney' as base_end,
           (target_date + time '07:00')
               at time zone 'Australia/Sydney' as target_start
    from recent
)
select price_date, target_date,
       base_end at time zone 'utc' as candidate_base_end_utc,
       target_start at time zone 'utc' as candidate_target_start_utc,
       extract(epoch from (target_start - base_end)) / 3600
           as candidate_gap_hours,
       collected_at < target_start as current_copy_received_before_start
from boundaries
order by price_date;
commit;
```

## 输入历史证据的限制

`JdbcGoldDailyBarRepository.saveAll()`在相同供应商、标的、标签日期冲突时更新OHLC、接收时间和确认依据。当前表不是不可变的首次接收归档。不能用上述5个接收时间替历史的每一天证明当时已知，也不能反过来宣称全部历史日线是假行情或从未可用。

`GoldDatasetBuilder`已明确把本次Clock作为当前闭市核验时刻，不冒充历史OHLC可得性；宏观归档的D-1已知版本也不能自动证明黄金日线当时的最终值可得。历史价格回放仍有研究价值，但不是实时发布时间的完整复刻。

官方[时区说明](https://support.twelvedata.com/en/articles/5745849-timezones)说明Forex默认悉尼时区；[历史范围参数说明](https://support.twelvedata.com/en/articles/5214728-getting-historical-data)说明查询边界与条数。本轮重新打开两篇说明，均未提供XAU/USD悉尼07:00日线最终发布时间保证。因此本轮不将候选规则升级为正式确认来源。

## 多轮失败原因与裁决

1. 九项原研究及后续VIX增量研究都没有证明满足既定门槛的稳定涨跌优势。汇总来自已落盘报告，本轮没有重跑训练，不能称为十个独立新盲测。
2. 已修复收敛、数值条件、宏观历史版本等问题后仍失败，不能继续把同一问题当作所有失败的解释。
3. VIX同条件实验为价格353/720、价格加VIX349/720，三个验证折均下降；这只否定本次表达与模型下的增量效果，不证明任何VIX用法都无效。
4. 本轮确认的零生成窗口与事后当前副本，是实际发布与历史回放之间的真实性缺口；尚不能证明它们导致上述旧开发集的预测错误。
5. 正式预测仅两条，统计研究与正式GLM链路不同。工程通过、旧开发分数或候选时段MATCHED，均不是正式未来准确率提高的证据。

## 下一步的约束，不是已实现功能

保留“下一有效黄金日收盘相对基准收盘”的方向目标，但必须在下一轮设计中明确它与“完整时段开始前预测”的区别。发布时间已经进入目标时段时，需要显式展示，不能称为完全未开始的行情预测；如果使用该时段已经发生的价格信息，历史实验也必须在同样的信息截止时刻比较基线。

尚未选择固定发布分钟数或正式截止规则，不凭空宣称30分钟、一小时或其他数字是供应商保证。也不为了有预测而使用未结束的完整OHLC。

正式合同需要一起解决：模型调用前后截止检查、承诺目标和依据版本持久化、真实接收证据、结算目标一致性、旧记录未知资格与可信准确率分层。不能只添加一个数据库缺价格检查，也不能把旧记录事后升级或移动目标。

本轮属于真实证据推进，不是代码修复或准确率改善。总目标继续进行；下一轮不能重复运行本只读汇总作为新进展，应把这些可行性约束落实到明确的发布合同设计，或取得足以支持该合同的新来源证据。
