# 黄金闭市确认：生产获取入口修复

## 本轮结论与边界

基线 `ba621b92b29b27993c10731a01016ac360262743`。
本轮把上一轮核实的 `/quote?symbol=XAU/USD&eod=true` 合同接入生产获取入口。
这是持续提高预测可信度工作中的一个实际修复步骤，不是预测模型增益，也不是全链路闭市确认已经完成。

## 失败原因与路线判断

原 `fetchDailyBars()` 只调用 `/time_series`。该接口响应没有单根日线的结束标记，返回列表本身不能证明每根蜡烛已结束。
后续同步服务仅排除周末；工作日尚未结束的行仍可被保存。
接口名称包含 EOD、价格字段叫 close、本地日期已经过去，都不能单独替代供应商显式合同。
这轮继续采用上一轮实测可用的 quote eod=true，并拒绝跨响应不一致；没有继续猜收盘钟点。

该缺口是当前代码允许的错误路径，不证明旧数据库实际发生过错误结算，更不能据此解释多轮历史准确率不足的全部原因。
方向模型仍未获得新的样本外增益证据；最终留出集不打开，不改标签、阈值或晋级标准。

## 本轮实际改动

- 生产获取依次请求普通日线和已结束交易日报价；确认接口失败则本次获取失败。
- 确认标的必须为 XAU/USD；日期不得晚于观察时刻的 UTC 日期。这个护栏不是推算收盘时刻。
- 必须存在确认日对应日线；该日开、高、低、收四项以 BigDecimal 精确相等。
- 只返回确认日及以前的日线，不用 is_market_open 或纽约前一天推导截止日。
- 拒绝缺字段、无效日期、无效 OHLC 关系、重复日线、非日线周期、非字符串价格。
- 价格遵守供应商十进制字符串合同，不接受已经可能经 DoubleNode 舍入的 JSON 数字。
- HTTP 错误不附带含请求 URL 的 RestClient 原始异常；状态/日期/格式错误均用受控中文信息。
- 保守校验整包日线后再截断：未确认行畸形也拒绝整批，不静默吞掉异常行。

本轮没有增加数据库字段，没有给旧行补确认标记，没有运行生产同步、结算或新模型实验。

## 未完成要求与下一步

当前 `GoldDailyBar` 和 `JdbcGoldDailyBarRepository` 仍只有采集时间，没有确认来源、确认日期、确认时刻。
`GoldForecastResolutionService` 仍只验证目标日期/采集时间合理；旧库中未确认行仍可能被读取。
所以不能说同步、快照、结算和历史样本已共享同一确认依据。

下一步必须保存确认出处和边界，并让读取方检查它：

1. 用真实新获取结果建立证据；旧行默认未确认，不按日期自动回填。
2. 价格被覆盖时，旧确认不得继续生效；写入价格与依据应原子提交。
3. 结算先选基准日后第一根记录，再检查确认；不能先滤掉未确认目标而悄悄跳到更晚交易日。
4. 多日目标和特征窗口也不能因过滤未确认行改变 horizon 或漏掉已知间隔。
5. 快照、数据集、API 最新价共享相同信任边界；另核查预测生成时间是否真正早于目标结束。
6. 完成全链路后再同步真实数据、检查数据库和运行效果，不把工程测试结果冒充市场准确率。

持续目标保持进行中。本轮前一个市场合同核实是证据进展，本轮是生产入口修复和回归进展；仍未满足“未来预测变得更准确”的最终要求。
