# 滚动评测修复与供应商时段口径复核

## 本轮失败原因

正式预测评测的最近20条窗口使用`resolvedAt`降序。补结算很旧的预测会将它挤入近期窗口，让近期表现被运维执行顺序改变，而不是市场日期改变。此前回测链已有日期排序，正式预测链没有同步这一口径。

本轮限定修改已有评测的排序：目标行情日期降序、基准日降序、固定UUID升序，取20条。仍然是20条预测，不去重为20个日期。总体、分方向、版本和中性基线公式不变，不写库，不改旧结算结果。

## 外部数据口径：新的路线风险

主代理实际读取官方页面：

- [Twelve Data时区说明](https://support.twelvedata.com/en/articles/5745849-timezones)：Forex默认Australia/Sydney。
- [Forex API v2](https://support.twelvedata.com/en/articles/12520817-forex-api-v2)：说明该数据模块持续24/7供应，并列出贵金属XAU覆盖。它不是某一家伦敦金交易所的交易日历证明。
- [EOD说明](https://support.twelvedata.com/en/articles/12682324-end-of-day-eod-pricing-market-data)：区分初步价格与核对后价格；示例为股票，不能直接套用到黄金的精确收盘时刻。
- [API文档](https://twelvedata.com/docs)：网页检索不可完整加载，主代理HTTP读取后仅提取字段说明，显示部分接口datetime描述为区间开端。尚未证明本项目quote timestamp可作为收盘边界。

截至本轮，不将这些说明组合成未经证明的“纽约17点收盘”或“悉尼午夜收盘”。

### 真实只读接口汇总

`XAU/USD`、`1day`最近90根：2026-07-06至2026-10-03，共25根周末标签；其中24根不晚于上一轮实际quote EOD锚点2026-10-02，且24根都有high>low。当前同步直接丢弃周末行，需要重新核验。这里不把这些周末报价认定为正常交易时段，也不认定是假数据；只证明不能用“都没有价格变化”解释过滤。

`XAU/USD`、`1h`、`timezone=UTC`两根的可用性探查：status=ok、interval=1h、2条、最新datetime=2026-10-03 18:00:00，时区元字段仍为空。这只证明当前账户能取小时线，不证明完整历史覆盖、小时线结束状态或时区合同已验收。

请求没有入库，不输出OHLC原始值、带密钥URL或密钥。没有删除周末过滤，没有把未经核验的最新日线加入预测输入。

## 多轮总结与下一步

多轮确定性缺口包括：输入窗口确认、持久化精度、准备流程仍走旧价格源，以及本轮正式评测按补结算顺序选窗口。这些修复提高的是输入和评估一致性，不是模型预测能力证明。

现在应重新评估数据时段路线，不继续盲目叠特征：供应商持续报价与本地工作日日历可能不是同一合同。下一轮先核验可明确解释的日线口径；若原生日期/时段无法获得可核查定义，评估以有完整时间标记的真实小时线构建明确UTC区间的新版本数据合同。该备选必须验证时间标记、完整区间、覆盖、缺值拒绝、宏观可用时刻和版本隔离，不能把两条可用性探查直接升级成正式数据或换源成功。

生成前后截止校验、结算时间资格、旧记录可信统计分层仍未完成。旧结果只读且不补造时段证据；最终留出集继续封存。只有数据合同可复现后才进入冻结开发集实验，若多轮仍不能超过固定基线，再调整日级三方向任务路线，而不是降低标准。
