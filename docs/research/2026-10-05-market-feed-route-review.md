# 黄金数据路线再评估：完整聚合不等于目标市场身份

## 目标不变

目标仍是提高下一黄金交易日方向预测的真实样本外能力；每轮复盘失败，失败多轮时评估路线。
不是把“可用API、合法JSON、窗口匹配、测试通过”改称预测准确。
本轮查官方合同与访问条件，不调用模型，不读取最终留出集，不新建交易账户、不购买数据。

## 新查明的官方信息

[Twelve Data贵金属及外汇说明](https://support.twelvedata.com/en/articles/11850499-understanding-price-deviations-in-commodities-and-forex-data)
说明其报价为多源复合价格，默认mid-price，不是特定经纪商的可成交报价。
该说明不能解释同一来源跨周期收盘差异或重复日线标签；不能用“跨来源价格可以不同”豁免内部问题。

[Forex API v2](https://support.twelvedata.com/en/articles/12520817-forex-api-v2)
明确覆盖XAU等贵金属，并说明24/7提供，包括周末与节假日。
由此可见，周末存在小时数据不等于伦敦黄金市场在正常交易。
重分发另需授权，原始行情继续只留本机忽略目录。

[API文档](https://twelvedata.com/docs)
规定日线及以上忽略timezone参数。给日线追加UTC参数不能消除标签/时段问题。
小时数据可请求UTC，但不因此获得原生日线或目标平台的闭市合同。

## 多轮证据合并

| 轮次 | 新证据 | 否定/保留结论 |
| --- | --- | --- |
| 重复标签 | 最新日线重复日期且OHLC不完全相同 | 不可随意去重挑一条 |
| 小时交叉核验 | 23小时完整，收盘不匹配 | 不可把缺口当本次唯一原因 |
| 起点前移 | 24小时四项均不匹配 | 否定起点前移即可修复 |
| 结束后移 | 单日24小时四项匹配 | 保留单日候选，未认证通用规则 |
| 相邻日 | 延长窗口与下一原候选重叠1小时 | 否定直接推广修复 |
| 官方合同 | 24/7复合中间价 | 独立聚合不自动对应用户关注市场 |

现有行情不是凭空生成的假数据；问题是时段身份、重复标签和目标口径不够可靠。
既不能称所有历史价格虚假，也不能继续用猜出来的边界生成可信成绩。
统计模型多轮无稳健优势、本地模型事实解释错误，是另两层失败，仍需单独修复和新样本验证。

## 三条路线与推荐

1. 保留原供应商，但取得XAU/USD日线起止时刻、DST切换、重复标签与EOD最终性的明确解释。
   这是最小变更；当前尚无供应商答复，不能写“合同已认证”。
2. 换成时间与价格口径明确的真实来源，先验证账户可访问XAU、当前日线、已完成标志及历史范围。
   可优先评估OANDA v20，不直接承诺可用或更准；报价仍是该来源口径，不是统一伦敦唯一价格。
3. 固定UTC小时聚合作为另一个研究目标。数学上可连续，但改变预测对象，不能静默替代原目标。
   当前不推荐把这条路线直接上线，也不为它沿用旧准确率。

推荐先完成路线1的合同核实；若供应商不能解释或修复，再验收路线2。
不再继续无限时段扫描、旧提示词重试或旧开发集搜索。

## 替代来源实际条件

[OANDA蜡烛定义](https://developer.oanda.com/rest-live-v20/instrument-df/)
提供起始时间、bid/ask/mid与complete标志；complete表示结束时间不在未来，不保证永不修订。
[定价接口](https://developer.oanda.com/rest-live-v20/pricing-ep/)
列出dailyAlignment、alignmentTimezone，并要求Bearer令牌和账户ID。
本机Process/User环境只检查配置是否存在：OANDA_API_TOKEN=false，OANDA_ACCOUNT_ID=false。
不输出密钥，不以文档存在冒充真实接口成功；账户地区及XAU可用性仍需实查。

[Dukascopy历史导出](https://www.dukascopy.com/wiki/en/development/data-export/)
当前官方批量导出说明使用AWS Requester Pays，需要AWS凭据并会计费。
本轮未启用计费或批量下载；不能沿用“所有历史下载都免费”的旧印象。
这不证明其所有其他访问方式收费，也不证明其当前黄金数据已获取。

## 供应商需确认的技术问题

供用户与数据供应商沟通，不由本项目自动发送，也不附凭据或未授权原始数据：

- XAU/USD日线日期标签的确切[start,end)定义及使用时区是什么？
- 2026-10-04的两条不同日线为何同标签？如何获取唯一已完成条目而不随意去重？
- 2026-10-03原生日线能由21:00Z至次日21:00Z的24小时复原，
  却不能由Sydney本地7点两端独立换算的23小时复原，DST切换日采用何种边界？
- quote(eod=true)的timestamp/last_quote_at分别代表什么？如何判断日结完成及后续修订？
- 日线和小时线是否使用相同价格类型、聚合源及日结修订规则？

## 当前实施边界

未切换生产数据源、未改GoldSession、未写新行情、未生成新预测成绩。
新口径涉及预测对象、输入、目标结算和成绩隔离，需在明确数据合同后独立设计，
不把研究层小工具未经验收接入正式服务。
本轮证据是官方合同和真实访问前置条件，不是准确率提升。
继续获取真实新样本需要供应商澄清，或用户可提供且合法访问的替代行情凭据/数据合同。
