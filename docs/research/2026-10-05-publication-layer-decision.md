# 发布层修正：严格开盘前与盘中30分钟研究分离

## 为什么调整实验路线

前轮发现的零发布窗口不能靠换模型解决。重读既有实证报告后，
Twelve Data悉尼07:00日线边界并非单纯由周开盘说明猜出：
2026-10-04-gold-session-source-probe.md记录了28个完整小时区间与原生日线OHLC精确一致。
但这仍只是实测候选，不能认证所有时段或每天的供应商发布时点。

官方[时区说明](https://support.twelvedata.com/en/articles/5745849-timezones)
确认Forex默认悉尼时区；[官方文档](https://twelvedata.com/docs)
说明日/周/月线不受timezone参数改写，不能通过加timezone=UTC来重新定义原生日线。
[Commodity参考页](https://twelvedata.com/exchanges/commodity?group=reference)
将XAU/USD列为聚合报价，展示悉尼时区及24/7元数据；这也不能直接认证伦敦交易时段。
本轮官方文档通过搜索结果可读取参数段，仍未找到黄金日线每日07:00的正式合同。

即使候选日线边界正确，连续日线结束与下一根开始相接时，
收盘数据传输和模型耗时也会把发布推到目标时段内。这是任务时间定义的问题，
不能将盘中预测悄悄称为开盘前全日预测，也不能解释成模型方向已经改进。
当前正式GoldForecastPublicationPolicy原本允许在目标候选时段内发布，
研究协议反而采用更严格开盘前限制，两者必须明确区分。

## 本轮落地：只改变研究执行工具

LocalEvidenceRun保留原默认严格模式，并新增显式--in-session选项：

| 层 | 固定时间要求 | 输出publicationLayer |
| --- | --- | --- |
| 默认严格模式 | 基准候选结束后、目标候选开始前；没有窗口就拒绝 | BEFORE_SESSION |
| 显式研究模式 | 目标候选开始后至开始+30分钟，结束边界不含 | IN_SESSION_30_MIN |

盘中30分钟参数在任何该模式真实模型调用之前固定，不依据命中结果调整。
两次配对请求都必须在固定截止前完成；超时或越线保留失败，不能后补成功。
对连续工作日该模式在数学上有30分钟窗口，不代表供应商会在30分钟内提供完整确认数据。
如果供应商迟发导致不可用，记录失败/跳过并评估路线，不自动放宽截止来凑样本。
默认模式和新模式使用不同协议标识及文件名，成绩、覆盖率和失败率不得混算。
模型、固定种子、温度、方向合同及原始输入保持既有配置；不增加盘中行情或新闻输入。

所有输出仍researchOnly=true、trustedAccuracyEligible=false、officialSessionCertified=false。
新研究层预测的是从已有基准收盘到目标标签收盘的最终方向；
发布时目标时段已经开始，不能说提前预测了整个目标时段，也不能用它代表开盘前准确率。
依然只能等后续真实已确认收盘后评分，不能用盘中价格代替结算。
正式生成、正式页面、历史记录、模型晋级门槛及最终留出集全部未改动。

## 本轮验证

- 工具javac复编通过。
- 离线--window-check实际执行8项：工作日默认零窗口拒绝、新模式开始前拒绝、
  开始瞬间允许、29分59秒允许、30分边界拒绝、越线拒绝、周末默认窗口允许、基准未闭拒绝。
- 两种模式均用已有真实10月2日冻结输入执行，退出1：NO_NEW_BASE_DATE。
- 未发送新的模型请求，未生成配对结果，未测新样本命中率。
- 时间测试只有日期和时刻，不是伪行情或伪模型输出。
- 生产Java未改动，本轮不以此前881项回归代表新模式正向实测。

从项目根目录可复现离线边界检查：

```powershell
$probePath = 'D:\workFile\demo-ai\backend\target;D:\workFile\demo-ai\backend\target\classes;' + (Get-Content backend/target/probe-classpath.txt -Raw).Trim()
javac -encoding UTF-8 -cp $probePath -d backend/target docs/research/probes/LocalEvidenceRun.java
java '-Dfile.encoding=UTF-8' -cp $probePath LocalEvidenceRun --window-check
```

真实执行须先用MacroPromptProbe的新快照UUID与evidence选项导出，
再提供实际冻结文件、已存在结果目录及正确目标标签日期；
只有显式追加--in-session才选择新研究层。没有新日期，不创建或伪造输入。
目录内已有同日期同层结果必须保留；工具不自动重试，不能换目录绕过一次性规则挑结果。

## 多轮归因与下一轮检查

旧统计模型多轮无稳健优势；本地单规则和宏观候选又暴露事实解释错误；
引用门槛只能验证部分引用，不能证明自由文本推理；严格日发布协议还存在时间不可能性。
不能把所有失败都归于一个模型参数，更不能承诺这些工程修正就提高命中率。

下一轮优先核验新日期确认数据的实际到达时刻，再运行按固定层声明的真实配对，
保存全部请求/回执及结构拒绝。若没有合格数据，保持无成绩，而不是用旧样本替代。
结果先分别报告事实错误率、方向准确率、覆盖率和时间资格；不同发布层不得拼成排行榜。
如固定模式长期没有可用输入，应审查数据发布合同/来源，而非无限增加提示词。
