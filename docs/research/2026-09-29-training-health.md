# 黄金预测训练体检与宏观历史版本审计

日期：2026-09-29。被检查的产品提交：`138abf1dde443763dada3caae6d745a43fe08eb4`。

## 结论

这次拿到了两个具体证据，而不是又换一个模型碰碰运气：

1. **已找到历史数据可得性泄漏的真实样例。** 2024-11-01 当时的 FRED 历史版本没有该周广义美元指数，但本地历史查询会取到后来采集、修订后的值。之前仅按观测日期防未来数据不够。旧宏观特征回测不能作为无泄漏的正式验收依据。
2. **默认五轮训练没有充分性保证，但增加轮数还不足以得到可采用的方向模型。** OHLC 内层验证由 329/720 提高到 343/720，仍低于同日期多数类的 347/720；下跌召回明显退步。没有将 80 轮配置应用到产品，没有选择新的正式模型。

这两点不能被解读为“已经找到所有预测错误的唯一原因”。本轮没有完成未来准确率提升，也没有宣称修复历史时点必然提高分数。

## 一、真实宏观样例：不是数据造假，是拿错了历史版本

对官方 FRED API 发出四次只读请求，限定观测日期为 2024-10-28 至 2024-11-01，分别指定 `realtime_start = realtime_end = 2024-11-01` 和 `2024-11-08`。

| 序列 | 截至 2024-11-01 的历史版本 | 截至 2024-11-08 的历史版本 | 当前本地 2024-11-01 观测记录 |
| --- | --- | --- | --- |
| DFII10 实际利率 | 返回 4 条，最后为 10-31；没有 11-01 | 返回 5 条，11-01 为 2.04 | 2.040000，2026-08-26 采集 |
| DTWEXBGS 广义美元指数 | 该观测区间返回 0 条 | 返回 5 条，11-01 为 125.0403 | 124.807600，2026-08-27 采集 |

这里的 DTWEXBGS **不是 DXY**。美元指数的本地数值还与 2024-11-08 历史版本不同，表明不仅存在发布滞后，也存在历史版本差异。

当前代码路径：`GoldDatasetBuilder` → `GoldResearchSnapshotService.createSnapshot(asOf)` → `JdbcMacroObservationRepository.findRecent`。查询只有 `observation_date <= asOf` 和 `superseded_at is null`，所以回到 2024-11-01 时会使用表中 11-01 的最新记录，无法表达“当时尚未公布”。`FredSeriesClient` 也没有请求或保存历史 real-time 版本区间。

本轮确认的是上述具体样例及查询语义缺陷，不是所有历史日期的完整污染比例，也没有量化它造成的准确率变化。FRED 的日级版本仍不能单独证明预测截止时刻之前的精确日内可得性。

原始证据：[官方 API 摘录](2026-09-29-fred-vintage.json)、[本地数据库只读摘录](2026-09-29-local-macro-audit.json)、[只读查询探针](probes/fred-vintage.ps1)。语义依据：[FRED observations 参数说明](https://fred.stlouisfed.org/docs/api/fred/series_observations.html)、[real-time period 定义](https://fred.stlouisfed.org/docs/api/fred/realtime_period.html)。

## 二、训练体检怎样避免再次消耗外层验证集

- 只查 `twelve_data / XAUUSD` 且 `price_date < 2024-11-11`：4382 根真实日线，2008-01-15 至 2024-11-08。SQL 层排除旧开发集和最终留出集，不只是训练时忽略它们。
- 按原 OHLC 公式和 ±0.5% 标签构造 4361 条初始训练期样本，类别数量为上涨 1197、中性 2088、下跌 1076，与上轮首折训练数量一致。
- 只使用真实 20 项 OHLC 特征，不查询宏观，不伪造未用的 16 项宏观/基础特征，也不按宏观齐备情况筛日期。
- 原始日线 SHA-256：`68b98d2cafb416118b5019bb59c87c33614c547148792a79aa854d2974d3b9f0`。
- 初始训练期最后 720 条分为三个连续 240 条内层验证块，使用扩展训练窗口；每块清除 `targetDate >= blockStart` 的边界样本。
- 三个预定训练检查点：5、20、80 轮。优化器、种子、标签、数据、特征和标准化方法不变，不加权、不加正则化，也不根据结果追加检查点。
- 标准化只拟合各折训练数据；显式五轮训练与既有默认训练器的概率差、固定种子重复训练差均为 **0**。
- 一个模型固定评估整块 240 条，不进行旧实验的每 20 日重训，因此本报告不能与旧 240 条开发分数直接相减。

## 四、下一步决策

1. **不采用“改为 80 轮”作为本轮修复。** 不再往同一诊断上追加轮数、权重和窗口直到出现漂亮数字。
2. **优先闭环宏观数据时点。** 历史数据需要保存来源版本和历史可见区间，重建快照时按预测截止时刻选择当时已知版本；没有证据的值不能靠固定延迟一天、补零或最新值回填。日内发布时间不明确时必须声明保守日级口径。
3. **OHLC 诊断保持独立。** 它绕开本轮宏观版本缺陷，不代表历史价格修订/交易日收盘可见时刻问题已经完全解决。
4. **训练诊断还缺独立收敛参照。** 后续可以在同样训练内时间块，用固定、可验证收敛的求解器判断 SGD 优化误差；求解器和正则化要分开检验。不能先看最终留出分数再选择。
5. 只有冻结的方案经过独立、同日期评估，方向准确率、下跌识别、覆盖率和概率误差都符合预先门槛，才讨论接入正式预测页。当前正式页面仍是 GLM 链路，本次没有修改它。
