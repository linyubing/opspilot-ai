# 黄金下一交易日预测：准确率改进可行性调研

调研日期：2026-09-29。核对代码：`17f285e`。本轮只调研，不修改产品代码、不运行新的训练实验、不切换正式模型。

## 一、结论先行

有继续研究的合理空间，但目前没有证据保证某个下一步方案能提高本项目的未来准确率，更没有依据承诺稳定达到 60%、70% 或支持重仓。

推荐先做“数据时点与训练充分性诊断”，不再直接尝试第三种权重/窗口，也不立刻换 LSTM 或大模型。这是对调查顺序的建议，不是声称诊断本身会提升命中率。

目标不变：预测下一黄金交易日的真实行情，并用之后实际行情检验。不能把它换成更容易做出高分的长期趋势、缩减覆盖率或事后筛选日期。

## 二、前两轮到底说明了什么

以下为已经保存的真实实验，不是文献中的数字，也不是本次新训练的结果。

| 实验 | 已知结果 | 可以得出的结论 | 不能得出的结论 |
| --- | --- | --- | --- |
| 标准化后截取近期 252/504 条训练样本 | 三组特征共六种窗口均低于全历史训练 | 这两个固定窗口在现有开发区间失败 | 所有市场适应方法都无效 |
| 按类别数量加权 | 三组完整样本准确率均下降 | 固定的逆频率权重方案不采用 | 所有类别处理方法都无效 |
| 更早的训练标准化 | OHLC_20 从 88/240 提高到 103/240 | 量纲处理影响了本开发集的效果 | 已经证明未来稳定有效 |

OHLC_20 加权后，下跌命中从 8/57 增至 18/57，但误报下跌从 16 次增至 47 次，总命中从 103/240 降至 91/240。模型只是改变了错判分布，没有提高整体判断能力。

前两轮有固定样本对照，但还没有先用训练诊断说明“窗口长度”或“类别权重”就是主要瓶颈。接下来应补这个证据环节。

本项目较好的标准化开发结果仍是 103/240，即 42.92%；对应多数类基线是 90/240，即 37.50%。这些不是最近 2026 年行情的独立验收结果，评分区间仍为 2024-11-11 至 2025-10-15。

本地证据：[标准化与窗口结果](../superpowers/specs/2026-09-21-gold-accuracy-improvement.md)、[类别加权结果](../superpowers/specs/2026-09-29-gold-class-balance-results.md)、[原始加权响应](../superpowers/specs/2026-09-29-gold-class-balance-results.json)。

## 四、当前项目发现的具体问题

### 1. 训练是否充分，还没有证据

`TribuoGoldTrainer.java:77` 使用 `new LogisticRegressionTrainer()`。Tribuo 4.3.2 官方说明它是便捷默认类：AdaGrad 学习率 1.0、训练 5 轮；需要改变训练细节时使用 LinearSGDTrainer。

这证明参数是默认值，不证明五轮一定不够。当前实验报告没有展示完整训练目标的收敛曲线、训练内验证曲线或独立收敛求解器对照，不能据此断言欠拟合，也不能直接把轮数改大当作修复。

值得验证的是：相同训练样本与特征下，充分收敛的逻辑回归是否与当前输出接近；如果训练拟合仍可改善，再检查这种改善能否传递到训练内部的后续时间段。正则化可作为限制过拟合的候选，而不是保证更准的开关。

依据：[Tribuo 默认训练器](https://tribuo.org/learn/4.3/javadoc/org/tribuo/classification/sgd/linear/LogisticRegressionTrainer.html)、[支持停止条件与正则化的逻辑回归参考实现](https://scikit-learn.org/stable/modules/generated/sklearn.linear_model.LogisticRegression.html)。两种求解器的“迭代”单位不同，不能简单比较 5 与 100。

### 2. 历史宏观数据可见时点没有闭环

已核对调用链：

- `GoldDatasetBuilder.build()` 调用 `GoldResearchSnapshotService.createSnapshot(asOf)`。
- 快照调用宏观仓库 `findRecent(seriesId, asOf, limit)`。
- `JdbcMacroObservationRepository.java:279` 附近只限制 `observation_date <= ?`，并取 `superseded_at is null` 的最新版本。
- `FredSeriesClient.fetch()` 没有设置 `realtime_start/realtime_end`，解析也没有保留历史版本可见区间。
- `MacroObservation` 的 `collectedAt` 是本系统采集时间，不等同于历史首次发布时间。

FRED 官方明确区分“今天知道的过去数据”和“历史当时知道的数据”；默认 real-time period 是今天，可以用 ALFRED 的历史区间检索过去已知信息。

因此这是已证实的时间语义缺口，但本次尚未逐条比较历史版本，不能宣称已经量化了它对准确率的影响。修正后分数可能下降，下降不表示修正无效。

后续需要保证因子在预测截止时刻已经可得；ALFRED 的日期版本信息也不能单独证明日内精确发布时间。不能随意统一延迟一天，更不能用今天的采集时间冒充十年前的发布时刻。

来源：[FRED real-time period 定义与默认值](https://fred.stlouisfed.org/docs/api/fred/realtime_period.html)。

### 3. 重复使用同一开发区间，已经不是新的独立证据

现有滚动流程确实排除了目标日未到的训练标签，也没有用尾部留出集训练或打分。这些保护应保留。但我们已在同一段 240 条开发样本上比较多种模型、特征、窗口和权重；不能再把该区间的最佳结果当作完全未见的验证效果。

Cawley 与 Talbot 的研究说明，模型选择本身也会过拟合评估数据。推荐把选参数放进每个训练区间内部的时间分区，外层只评价冻结的选择流程；标签跨期时还要按目标日期隔离，不能随机打乱金融时间序列。

改验证方法不会直接制造预测信号，但能避免把偶然提升误认为真实进步。

来源：[模型选择过拟合论文](https://jmlr.org/papers/v11/cawley10a.html)、[嵌套验证说明](https://scikit-learn.org/stable/auto_examples/model_selection/plot_nested_cross_validation_iris.html)、[时间顺序分区](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html)。嵌套验证示例使用鸢尾花数据，其中随机 KFold 不能原样照搬到本项目。

### 4. 实验模型与正式预测不是同一个对象

当前正式调用链是 `GoldForecastGenerationService.generateAndSave()` → `GoldForecastGateway.generate()` → `SpringAiGoldForecastGateway` → GLM；统计模型实验则由 `WalkForwardService` 调用 Logistic/XGBoost。

所以统计实验变好，不等于当前页面的 GLM 预测变好。后续必须标明每条预测的模型来源、数据截止时刻与结算口径，并评估实际要交付的那条链路。候选未通过独立验收前，不能直接替换正式方向。大模型可以作为有来源的解读层，但这只是可讨论的架构方向，本次没有实施。

### 5. 指标与用户期待需要保持一致

`GoldForecastRule` 定义大于 +0.5% 为上涨、小于 -0.5% 为下跌，其余为中性。这不等于“只要收盘比昨天低一点就算下跌”。本次不改变标签，避免通过改变任务得到更高数字。

另外，BASE_16 包含价格与宏观特征，不是 16 个纯动量特征；OHLC_20 虽不向模型输入宏观值，统一构建器仍会要求宏观因子完整。这两点会影响后续消融实验的解释。

## 五、哪些方向值得做，哪些先不做

| 方向 | 本次判断 | 理由 |
| --- | --- | --- |
| 核查数据可见时间、标签时点、训练收敛与正则化 | 优先诊断 | 对应明确的代码缺口或尚未验证的训练假设，成本可控 |
| 补入当时可得的跨市场因子、宏观事件信息 | 条件性备选 | 可能增加信息，但需先核实数据来源、历史发布时间与费用；不能拿事后新闻解释冒充事前预测 |
| 训练内有限选型 + 时间外层验证 | 必需的评价纪律 | 用于判断是否真改善，不是提升准确率的算法本身 |
| 概率校准与拒绝低把握信号 | 后置 | 可以改善概率解释或条件命中率；必须同时报告覆盖率，不能冒充全样本更准 |
| 继续随意换窗口/权重、堆 LSTM/大模型/多智能体 | 目前不建议 | 本次未找到足以证明这些会提升本项目下一日三分类的直接证据 |

尤其是常见的温度校准：同一正温度不会改变最大概率类别，因此本身不提高完整样本方向命中率。官方文档也明确说明这一点。来源：[概率校准说明](https://scikit-learn.org/stable/modules/calibration.html#temperature-scaling)。不能把它当作第三次“提高正确率”的承诺。

## 六、下一步建议与停止条件

下一步建议是一个有限诊断任务，而不是直接增加算法：

1. 固定要评估的预测对象、真实交易日、收盘口径及预测截止时间；保持现有三分类定义。
2. 先审计数据可见时间。宏观历史版本无法证明时，明确标记该路线不可用于正式历史验收；可单独建立不受宏观齐备条件筛选的 OHLC 诊断基线，但不能将其与不同日期的旧分数直接相减。
3. 在训练数据内部检查收敛和泛化，记录完整训练损失、后续时间块损失、类召回与稳定性。若改变求解器和正则化，分开对照，不把多个变化混成“轮数改进”。
4. 只有诊断支持某一具体瓶颈，才登记有限候选、主要指标和选择规则；选型不读取原最终留出集。
5. 冻结候选后，在未参与选型的时间区间验收，与同日期多数类和原模型比较；报告完整命中率、覆盖率、逐类指标、概率误差与时间区块不确定性。
6. 若只改善训练拟合、不改善训练内后续时间块，停止增加训练轮数；若仍无法稳定超过朴素基线，结论应是现有输入尚无足够预测证据，转向数据/因子研究或明确不提供强方向结论，不继续消耗留出集调到好看。

这里没有批准修改正式预测，也没有声称前述诊断已经做完。调研完成后，下一轮实施应围绕这些可检验假设展开。
